## 1. 개요

### 1.1 제품 정의
사용자가 마신 위스키를 **도감처럼 수집·기록**하고, 쌓인 기록으로 **취향을 분석**해 **맞춤 위스키와 비슷한 위스키를 추천**하는 인터랙티브 대시보드 서비스(웹 우선, 모바일 반응형 → 이후 앱).

### 1.2 핵심 컨셉
**"마시는 즐거움에서 모으고 발견하는 즐거움으로"** — 게이미피케이션(수집·배지·퀘스트)과 데이터 시각화(맛 지도·레이더 차트)를 결합한다.

### 1.3 배경
- 국내 위스키·하이볼 소비가 대중화되면서 "무엇을 마셨는지 기록하고, 다음에 뭘 마실지 고르는" 수요가 커졌다.
- 기존 서비스는 **구매/픽업(커머스)**(데일리샷 등) 또는 **영문 중심의 방대한 DB**(Whiskybase, Distiller) 쪽에 치우쳐 있다. **한국어 · 취향 분석 · 수집 재미**를 함께 주는 서비스는 비어 있다.

### 1.4 목표
1. 한국에서 유통되는 위스키를 거의 빠짐없이 담은 **한국어 위스키 DB**를 만든다 (1년 내 국내 유통 SKU 커버리지 90% 이상).
2. 사용자가 **30초 안에** 한 잔을 기록할 수 있게 한다.
3. 기록이 쌓일수록 정확해지는 **취향 분석 + 유사 위스키 추천**을 제공한다.
4. 공유 카드, 위스키BTI, 연말 결산 같은 **바이럴 장치**로 자연 유입을 만든다.

### 1.5 비목표 (이번 범위에서 제외)
- 주류 직접 판매·결제·통신판매 중개 (법적 제약, §9.2).
- 증류소 역사·유래 같은 긴 백과사전식 글 (기획 원칙 유지 — 스펙과 맛 위주).
- 개인 간 바틀 거래·분양 기능 (주세법 위반 소지).

### 1.6 제품 원칙
1. **글보다 그림** — 설명은 2줄 이내, 나머지는 차트·아이콘·태그로.
2. **기록은 가볍게** — 필수 입력은 "마셨다 + 별점"뿐, 나머지는 선택.
3. **출처가 보이는 데이터** — 모든 수치에 출처와 검증 상태를 표시한다.
4. **동등 기능은 갖추고, 차별 기능으로 이긴다** — 기존 앱에 있는 기본 기능(검색, 리뷰, 바코드 스캔 등)도 빠짐없이 제공한다.

## 2. 타겟 사용자

### 2.1 페르소나

| 페르소나 | 설명 | 핵심 니즈 | 주요 기능 |
|---|---|---|---|
| **입문자 "하이볼러"** (25~34세) | 하이볼로 시작, 니트는 몇 번 마셔봄 | 실패 없는 첫 바틀, 용어 이해 | 위스키BTI, 입문 큐레이션, 맛 지도 |
| **성장기 "탐험가"** (28~40세) | 바(bar)를 자주 감, 10~30종 경험 | 기록, 취향 파악, 다음 바틀 추천 | 도감, 레이더 차트, 유사 추천 |
| **수집가 "캐비닛 오너"** (30~50세) | 홈바 보유, 한정판·독립병입 관심 | 보유 바틀 관리, 희소 데이터 | 가상 바, 잔량/산화 관리, 배치 단위 기록 |
| **바텐더·크리에이터** | 바 운영자, 유튜버, 블로거 | 큐레이션 노출, 팔로워와 소통 | 전문가 큐레이션, 시음회 모드 |

### 2.2 핵심 유저 스토리
- 입문자로서, 몇 가지 질문에 답하면 **내 취향에 맞는 첫 위스키 3개**를 알고 싶다.
- 탐험가로서, 바에서 마신 위스키를 **사진 한 장이나 검색으로 30초 안에** 기록하고 싶다.
- 탐험가로서, 맛있게 마신 위스키와 **비슷하지만 더 싸거나, 조금 더 스모키한** 위스키를 찾고 싶다.
- 수집가로서, 집에 있는 바틀의 **개봉일·잔량**을 관리하고 **빨리 마셔야 할 바틀**을 알림으로 받고 싶다.
- 모든 사용자로서, 내 **도감 달성률과 취향 그래프**를 친구에게 자랑하고 싶다.

## 3. 경쟁 분석과 차별점

### 3.1 경쟁 서비스 비교

| 기능 | 데일리샷 (국내 커머스) | Whiskybase (글로벌 DB) | Distiller (글로벌 리뷰) | **Whisky Dex (본 서비스)** |
|---|---|---|---|---|
| 주 목적 | 구매·픽업 | 수집가 DB·컬렉션 | 리뷰·추천 | **수집·취향 분석·발견** |
| 한국어 / 국내 유통 반영 | ◎ | △ | △ | ◎ |
| DB 규모 | 판매 SKU 위주 | 매우 큼 (독립병입·배치 단위) | 큼 | 국내 유통 전수 + 글로벌 확장 |
| 맛 수치화·시각화 | △ | △ (텍스트 노트 위주) | ○ (플레이버 프로필) | ◎ (맛 지도·레이더·비교) |
| 게이미피케이션 | △ | △ | △ | ◎ (도감·배지·퀘스트) |

| 보유 바틀 관리 | × | ○ | △ | ◎ (잔량·산화 알림) |

> 기호: ◎ 강함 · ○ 있음 · △ 약함/부분 · × 없음. 실제 기능 범위는 출시 전 재점검한다.

### 3.2 기획서에 있던 차별점 (유지)
플레이버 매트릭스, 카테고리 트리맵, 도감 수집률·배지, 테이스팅 레이더, SNS 공유 카드, 위스키BTI, 전문가 큐레이션, 가상 바, 푸드 페어링, 체감 가성비 지수.

### 3.3 추가 차별화 포인트 (신규 발굴)

| # | 차별 기능 | 무엇이 다른가 | 왜 먹히는가 |
|---|---|---|---|
| D1 | **"한 축만 바꾸기" 추천** | 기준 위스키에서 "더 스모키하게", "더 달게", "더 싸게"처럼 한 축만 움직여 추천 | 사용자가 말로 설명하기 어려운 취향을 슬라이더 하나로 표현 |
| D2 | **블라인드 테이스팅 게임** | 친구와 블라인드로 마시고 앱에서 정답 맞히기·점수 경쟁 | 모임 콘텐츠, 재방문·바이럴 |
| D3 | **취향 궁합** | 친구와 취향 벡터 유사도(%) + "둘 다 좋아할 바틀" 추천 | 공유 동기, 선물 추천으로 연결 |
| D4 | **증류소 월드맵 정복** | 마신 위스키의 증류소가 지도에 스탬프로 찍힘, 지역별 달성률 | 수집욕을 지리적으로 확장 |
| D5 | **테이스팅 노트 도우미 (AI)** | 내가 쓴 자유 문장("달달한 빵 냄새")을 표준 아로마 태그(#몰티 #브리오슈)로 변환 | 초보도 전문가식 기록, 데이터 품질 향상 |
| D6 | **개인 평점 보정** | 사람마다 다른 채점 습관(후한/짠 점수)을 정규화해 추천에 반영 | 추천 정확도 향상 |
| D7 | **오픈 바틀 산화 타이머** | 개봉일·잔량으로 "빨리 마셔야 할 바틀" 알림 | 수집가 실사용 니즈, 푸시 리텐션 |
| D8 | **내 술장 하이볼/칵테일 메이커** | 가상 바의 보유 바틀만으로 만들 수 있는 레시피 추천 | 입문자 대다수가 하이볼 소비층 |
| D9 | **위스키 바 지도 + 바 메뉴 도감** | 바별로 보유 위스키를 크라우드소싱, "이 바에서 내 도감 미등록 위스키 n종" | 오프라인 경험과 도감 연결 |
| D10 | **월간 퀘스트·시즌 챌린지** | "이번 달 일본 위스키 3종", "셰리 캐스크 비교 시음" 등 | 목표 제시로 기록 빈도 증가 |
| D11 | **연말 결산 "Whisky Wrapped"** | 1년간 마신 양·최애·취향 변화를 스토리형 카드로 | 연말 대형 바이럴 이벤트 |
| D12 | **데이터 신뢰 배지** | 각 수치에 출처·검증 상태(공식/커뮤니티/AI 추정) 표시 | 신뢰도 자체가 경쟁력 |
| D13 | **시음회(플라이트) 모드** | 여러 명이 같은 플라이트를 동시에 기록하고 결과를 비교 | 바·동호회 B2B2C 확장 |
| D14 | **가격 히스토리 (정보 제공)** | 시세 추이 그래프와 목표가 알림. 판매 중개 없이 정보만 제공 | 구매 의사결정 지원, 가성비 지수와 연결 |

## 5. 비슷한 위스키 추천 상세 설계 (R4)

### 5.1 추천 모드

| 모드 | 사용자 질문 | 로직 요약 | 노출 위치 |
|---|---|---|---|
| **비슷한 위스키** | "이거랑 비슷한 거 뭐 있어?" | 맛 벡터 + 메타데이터 가중 유사도 Top N | 상세 페이지, 시음 기록 직후 |
| **더 저렴한 대체 (듀프)** | "이 맛인데 더 싼 거?" | 유사도 ≥ 임계값 AND 가격 < 기준가×0.7 | 상세 페이지, 위시리스트 |
| **한 단계 업그레이드** | "이거 좋았는데 다음엔?" | 같은 맛 방향 + 숙성·도수·가격 한 단계 위 | 높은 평점(≥4) 기록 직후 |
| **한 축만 바꾸기** | "이거보다 조금 더 스모키하게" | 기준 벡터에서 선택 축만 +Δ 이동 후 최근접 탐색 | 상세 페이지 슬라이더 |
| **품절·단종 대체** | "구할 수가 없어" | 판매 상태 = 단종/품절일 때 유사 + 국내 유통 중 필터 | 상세 페이지 배너 |
| **함께 좋아한** | "취향 비슷한 사람들은?" | 아이템 기반 협업 필터링 | 상세 페이지 (데이터 충분 시) |

### 5.2 유사도 계산

**입력 특징**

| 특징 그룹 | 항목 | 기본 가중치 |
|---|---|---|
| 맛 벡터 (핵심) | 10축: 단맛, 스모키/피트, 바디, 스파이시, 과일, 플로럴, 몰티/곡물, 오크/우디, 너티, 와이니(셰리/와인) — 각 0~5 | 0.55 |
| 아로마 태그 | 표준 태그 집합 Jaccard 유사도 | 0.15 |
| 캐스크 | 버번/셰리/포트/와인/럼/미즈나라 등 원핫 | 0.10 |
| 스타일 메타 | 국가·지역, 종류(싱글몰트/블렌디드/버번/라이…) | 0.10 |
| 스펙 | ABV, 숙성 연수(정규화), 피트 수치(ppm, 있을 때) | 0.10 |

```
sim(a, b) = Σ w_g · sim_g(a, b)
  sim_flavor = cosine(v_a, v_b)            # 10축 맛 벡터
  sim_tags   = |T_a ∩ T_b| / |T_a ∪ T_b|   # 아로마 태그
  sim_cask   = cosine(c_a, c_b)
  sim_meta   = 국가 일치 0.5 + 종류 일치 0.5
  sim_spec   = 1 − 정규화된 거리(ABV, 숙성, ppm)
```

- 가중치는 초기값이며, 클릭·위시 추가·이후 평점 데이터로 학습해 조정한다.
- **다양성 보정**: 같은 브랜드 결과는 최대 2개, 나머지는 MMR(Maximal Marginal Relevance)로 다양하게 섞는다.
- **개인화**: 로그인 사용자는 `최종점수 = sim × (1 + α · 개인 취향 적합도)`. 이미 마신 위스키는 기본 제외하고 토글로 포함할 수 있다.
- **콜드 스타트**: 맛 벡터가 없는 신규 위스키는 같은 증류소·캐스크·종류의 평균 벡터로 대체하고, "추정" 배지를 붙인다.

### 5.3 협업 필터링 (P2)
- 조건: 위스키당 평점 30건 이상, 활성 사용자 5,000명 이상일 때 켠다.
- 방식: 보정 평점(F-209) 기반 아이템-아이템 유사도 → 콘텐츠 기반 결과와 하이브리드 (데이터 양에 따라 비중 0 → 0.4).

### 5.4 추천 이유 설명 (F-506)
각 추천 카드에 다음을 표시한다.
- **공통점** 최대 3개: 예) "셰리 캐스크 · #건포도 #다크초콜릿 · 묵직한 바디"
- **차이점** 1개: 예) "스모키 +1.5, 가격 약 40% 저렴"
- 두 위스키의 레이더 차트를 겹쳐 보여 준다.

### 5.5 피드백 루프
- 카드별 👍 / 👎 / "이미 마심" 버튼.
- 추천에서 시작된 시음 기록의 평점을 추천 품질 라벨로 쓴다.

```
[수집]                [정규화]               [병합]                 [보강]            [검수]          [서빙]
공개데이터 ─┐        이름 정규화            엔티티 매칭             LLM 맛벡터·태그   검수 큐          검색 인덱스
국내 공공  ─┼──▶   (대소문자·연산자·      (바코드 > 브랜드+   ──▶  한국어명 생성 ──▶ (등급 부여) ──▶ 추천 벡터 인덱스
제휴 피드  ─┤        숙성·도수 파싱)        숙성+도수+캐스크           가격 정규화                       대시보드 집계
사용자 제보 ─┘                              퍼지 매칭)
```

- **엔티티 매칭 우선순위**: 바코드 일치 → (브랜드 + 표현명 + 숙성 + 도수) 일치 → 퍼지 문자열 유사도 ≥ 0.92 + 사람 확인.
- **계층 구조**: 브랜드 > 제품(Expression) > 에디션/배치 > 바틀(SKU: 용량·바코드). 도감 수집 단위는 "제품".
- **갱신 주기**: 공공 데이터 월 1회, 제휴 피드 일 1회, 사용자 제보 실시간 큐.
- **출처 추적**: 모든 필드에 `source`, `retrieved_at`, `confidence`를 남긴다.

### 6.4 바틀 이미지 전략
1. **기본 — 템플릿 일러스트**: 병 모양 템플릿 12종(둥근 병, 사각 병, 위스키 플라스크형 등) × 라벨 색·캐스크 아이콘 조합으로 자동 생성. 도감 통일감 확보, 저작권 문제 없음.
2. **공식 이미지**: 제휴 수입사·증류소 프레스 킷 이미지 (이용 허락 범위 내).
3. **사용자 사진**: 본인 촬영 사진은 업로드 약관에서 서비스 내 이용 허락을 받는다.

### 6.5 데이터 품질 KPI
| 지표 | 목표 |
|---|---|
| 국내 유통 SKU 커버리지 | 6개월 70% → 1년 90% |
| A·B등급 비율 (검색 노출 상위 1,000종 기준) | ≥ 95% |
| 중복 레코드 비율 | ≤ 1% |
| 사용자 제보 처리 리드타임 | ≤ 72시간 |
| 데이터 오류 신고 처리율 | ≥ 90% / 주 |

## 8. 화면 구성 (IA)

### 8.1 내비게이션
`홈(대시보드)` · `도감 탐색` · `기록하기(+)` · `내 바` · `마이`

### 8.2 홈 대시보드 레이아웃

```
┌──────────────────────────────────────────────────────────────────┐
│ KPI 바: 정복한 위스키 42 │ 도감 달성률 8.4% │ 최애: 셰리 싱글몰트 │ 평균 도수 45.2% │
├───────────────────────────────────────────┬──────────────────────┤
│ [탭] 도감 그리드 │ 맛 지도 │ 카테고리 트리맵 │ 나의 취향 레이더        │
│                                           │ (기간 토글)            │
│  ▣ ▣ ▣ ░ ░ ▣ ░ ▣  ← 컬러=마심, 실루엣=미수집  ├──────────────────────┤
│  ░ ▣ ░ ░ ▣ ░ ░ ░                           │ 이번 달 퀘스트 2/3      │
│                                           ├──────────────────────┤
│                                           │ 위스키BTI 배너          │
├───────────────────────────────────────────┤ 전문가 큐레이션 슬라이드 │
│ 최근 기록 기반 "비슷한 위스키" 추천 카드 ×4   ├──────────────────────┤
│ (공통점/차이점 표시)                         │ 커뮤니티 한줄평 피드     │
└───────────────────────────────────────────┴──────────────────────┘
```
- 모바일: 1열 세로 스택, 순서는 KPI → 퀘스트 → 추천 → 도감 → 레이더 → 피드.

### 8.3 핵심 플로우
1. **빠른 기록 (목표 30초)**: `+` → 바코드/사진/검색 → 별점 → (선택) 맛 슬라이더 → 저장 → 배지·도감 애니메이션 → 비슷한 위스키 추천 노출.
2. **BTI 유입**: 랜딩 → 테스트(비로그인) → 결과 카드 공유 → Top 3 → 위시 담기 → 가입.
3. **유사 추천 탐색**: 상세 → "비슷한 위스키" 탭 → 모드 선택(비슷한/저렴한/업그레이드/한 축 바꾸기) → 비교 레이더 → 위시 추가.

## 9. 비기능 요구사항과 법·규제

### 9.1 비기능 요구사항
| 항목 | 요구사항 |
|---|---|
| 성능 | 검색 응답 p95 < 300ms, 유사 추천 p95 < 500ms, 대시보드 첫 렌더 < 2.5s (4G) |
| 확장성 | 위스키 10만 건, 기록 1,000만 건까지 구조 변경 없이 확장 |
| 가용성 | 99.5% 이상 |
| 검색 | 한글 형태소·초성·오타 허용, 별칭 사전 |
| 접근성 | WCAG 2.1 AA, 차트에 텍스트 대체 수치 제공 |
| 보안·개인정보 | 개인정보보호법 준수, 위치·사진 메타데이터(EXIF) 제거, 최소 수집 |
| 다국어 | 한국어 우선, 영문 병기 구조 (향후 일본어 확장 고려) |

### 9.2 법·규제 체크리스트 (법무 검토 필수)
- **주류 통신판매 제한**: 온라인 판매·결제 중개를 하지 않는다. 구매 연결은 합법 스마트오더 사업자 제휴 링크로만 한다.
- **주류 광고 기준 (국민건강증진법 등)**: 제휴·광고 콘텐츠에 음주 미화, 과음 조장 표현을 금지하고, 경고 문구 노출 정책을 수립한다.
- **청소년 보호**: 만 19세 미만 이용 제한, 가입 시 연령 확인. 커머스·광고 연동 시 본인인증으로 강화.
- **개인 간 거래 금지**: 커뮤니티에서 바틀 판매·교환 글은 자동 필터링하고 신고 처리한다.
- **데이터 저작권·DB권**: 외부 데이터는 라이선스 범위 안에서만 쓰고, 리뷰 원문은 복제하지 않는다. 출처 표기를 자동화한다.
- **상표**: 브랜드명은 식별 목적으로만 쓰고, 로고·라벨 디자인은 템플릿 일러스트로 대체한다.
- **건전 음주 장치**: 주간 시음량 기록 시 과음 안내, 연말 결산에서 과음을 미화하지 않는 문구.

## 12. 리스크와 오픈 이슈

### 12.1 리스크
| 리스크 | 영향 | 대응 |
|---|---|---|
| 맛 벡터 품질 편차 (AI 추정값 오류) | 추천 신뢰도 하락 | 등급 표시, 상위 노출 제품 우선 검수, 커뮤니티 데이터로 계속 보정 |
| 대형 DB 제휴 실패 | 규모 목표 미달 | 공공·국내 수입 데이터 + 크라우드소싱으로 국내 커버리지 먼저 확보 |
| 법 규제 해석 리스크 | 기능 중단·제재 | 출시 전 법무 검토, 커머스 기능은 제휴 링크로만 |
| 기록 피로 (입력 귀찮음) | 리텐션 하락 | 필수 입력 최소화, 바코드·사진 인식, 퀘스트 보상 |
| 커뮤니티 불법 거래·스팸 | 법적·평판 리스크 | 키워드 필터, 신고 처리 SLA, 평판 점수 |
| 콜드 스타트 (초기 사용자 적음) | 협업 필터링 불가 | 콘텐츠 기반 추천으로 시작, 데이터 쌓인 뒤 하이브리드 |

### 12.2 오픈 이슈 (결정 필요)
1. 수익 모델: 프리미엄 구독(고급 분석·무제한 가상 바) vs 제휴 수수료 vs 브랜드 스폰서 큐레이션 — 조합과 시점.
2. 웹 우선 vs 앱 우선: 바코드·사진 인식 UX는 앱이 유리. PWA로 시작할지 결정.
3. 도감 수집 단위: "제품" 단위로 할지, 수집가를 위해 "배치/에디션" 단위 도감을 별도로 둘지.
4. 맛 축 표준: 10축 체계를 확정하고, 외부 데이터셋(예: 12축 Scotch 프로필) 매핑 규칙을 정해야 한다.
5. 수입식품정보마루 데이터의 대량 이용 가능 여부 (식약처 문의 필요).
6. Whiskybase·Distiller 등 제휴 협상 우선순위와 예산.
7. 연령 확인 수준: 자기 확인으로 시작할지, 처음부터 본인인증을 할지.
